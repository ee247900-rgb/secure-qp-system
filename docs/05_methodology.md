# Methodology

The system implements a 12-step secure workflow to ensure the integrity and confidentiality of the question paper from creation to distribution.

### 1. Question Creation
* **Description:** Subject Matter Experts (Question Setters) log in to the portal and enter individual questions along with metadata (subject, difficulty, marks).
* **Security Principle:** Segregation of duties. Setters only see their own questions.
* **Actors:** Question Setters

### 2. Question Review
* **Description:** Moderators review the submitted questions for accuracy, formatting, and relevance. 
* **Security Principle:** Peer review and RBAC (Role-Based Access Control).
* **Actors:** Reviewers / Moderators

### 3. Question Approval
* **Description:** Once reviewed, questions are approved and added to a master 'Question Pool'.
* **Security Principle:** State transition control. Unapproved questions cannot be selected for an exam.
* **Actors:** Reviewers / Moderators

### 4. Paper Compilation
* **Description:** An authorized Compiler selects questions from the pool to form a final Question Paper. This is done dynamically, and a final PDF is generated in memory.
* **Security Principle:** Least Privilege. Compilers do not see the whole pool, only the metadata to filter, or questions are randomly selected.
* **Actors:** Compilers / Chief Examiners

### 5. SHA-256 Hashing
* **Description:** The compiled PDF is hashed using SHA-256 to create a unique, fixed-size fingerprint of the file.
* **Security Principle:** Integrity. Any modification to the PDF will drastically change the hash.
* **Actors:** Crypto Engine (Automated)

### 6. Digital Signature
* **Description:** The system digitally signs the SHA-256 hash using a server-side private key (e.g., Ed25519). 
* **Security Principle:** Non-repudiation and Authenticity. Proves the paper was generated by the legitimate system.
* **Actors:** Crypto Engine (Automated)

### 7. AES-256-GCM Encryption
* **Description:** The PDF is symmetrically encrypted using AES-256 in Galois/Counter Mode (GCM). GCM provides both confidentiality and authenticated data.
* **Security Principle:** Confidentiality. The file is unreadable without the symmetric encryption key.
* **Actors:** Crypto Engine (Automated)

### 8. Shamir's Secret Sharing (Split Key)
* **Description:** The AES-256 key used to encrypt the paper is split into multiple shares (e.g., 5 shares) using Shamir's Secret Sharing algorithm. A threshold (e.g., 3) is required to reconstruct the key.
* **Security Principle:** Zero Trust / Key Custody Distribution. Prevents single points of failure and insider threats.
* **Actors:** Crypto Engine (Automated), Key Holders (Custodians)

### 9. Secure Storage
* **Description:** The encrypted PDF, the digital signature, and the metadata are stored in a secure cloud bucket (e.g., Supabase Storage). The key shares are securely distributed to the key holders' accounts.
* **Security Principle:** Defense in depth. Even if storage is breached, the data is encrypted.
* **Actors:** Cloud Storage System

### 10. Time-Locked Release
* **Description:** The system enforces a strict time-lock. Even if the threshold of key holders approve the release, the system will not reconstruct the key until the scheduled exam time minus a small buffer (e.g., T-30 mins).
* **Security Principle:** Temporal Access Control.
* **Actors:** Application Server

### 11. Secure Distribution with Watermarking
* **Description:** At the allowed time, exam centres request the paper. The server reconstructs the key, decrypts the paper in memory, applies a unique, dynamic watermark (containing the Centre ID and timestamp), and serves it over HTTPS to the centre.
* **Security Principle:** Traceability. Any leaked physical copy can be traced back to the specific exam centre.
* **Actors:** Exam Centre Coordinators, Application Server

### 12. Audit Logging & Monitoring
* **Description:** Every action (login, question creation, compilation, key share submission, download) is recorded in an immutable audit log.
* **Security Principle:** Accountability and Non-repudiation.
* **Actors:** Audit Layer (Automated)
